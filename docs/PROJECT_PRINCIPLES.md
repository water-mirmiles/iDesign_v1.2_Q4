# 项目原则

版本：1.0 · 最后更新：2026-10-11 · 来源：本轮用户要求、24 张截图和 iAMZ 开发协作流程。

1. **围绕鞋履设计闭环。** 项目、品牌、款号、参考素材、创作节点与未来评审/打样共用项目身份；品牌差异通过配置表达，不能把单一品牌当作平台规则。
2. **截图是视觉验收依据。** 保留布局、字体层级、留白、色彩、卡片、弹窗、浅深主题及画布关系。逐屏比较真实渲染；未经对比不宣称“像素级一比一完成”。截图内的红色批注是说明内容，不默认进入正式 UI。
3. **产品事实与演示分开。** 示例项目和统计可支撑交互验证，必须标记来源；不能编造企业数据、风险结果或 AI 输出。禁用能力不用虚假成功提示替代。
4. **公司资产可追溯是目标。** 当前仅浏览器存储，正式阶段应具备项目/版本/资产/任务稳定 ID、源图保留、不可变历史、权限和审计。UI 原型不能算这些已实现。
5. **保护用户作品。** 设计修改先保留源数据；恢复、导入或迁移不得覆盖其他项目、品牌或原版本。涉及存储或导出必须校验刷新与文件结果。
6. **单一开发源与单份事实。** web/ 是当前唯一前端源，产物可重建；PRD 管需求、FEATURES 管事实、ITERATIONS 管证据、README 管入口。禁止并行维护多个“最新版”。
7. **小步、可恢复、可审阅。** 明确每轮验收，分支开发和本地恢复点；不强推、删历史或无理由换技术栈，回退优先 revert。
8. **文档随代码即时更新。** 在同一工作轮和提交批次更新；提交前与 PR 门禁检查，不能等发布后补写。文档更新不需要后台定时任务。
9. **验证有层次。** 语法/单元、浏览器行为、视觉对照、外部集成、用户验收分别记录。自动检查通过仅是工程证据，用户确认才是业务接受。
10. **密钥与权限在服务端。** 正式身份、品牌授权、企业 API 与 AI 凭证不能放浏览器或 Git。收费任务、合并、生产部署按明确授权执行。

规则变更也要在 PR 说明理由和影响，不通过悄悄修改原则来绕过检查。参考 iAMZ 的流程，不移植其 A+ 版式、Amazon 发布或业务字段为 iDesign 需求。
